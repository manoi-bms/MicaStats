# StackChan companion screen

Status: complete

The owner confirmed USB control works and asks for a modern, professional,
informative and friendly physical screen, backed by further research. Preserve
the working USB/BLE stream protocols, face controls, bounded motion and quiet
mode. Research official LCD/font/controller APIs and glanceable UI principles.

Use the 320x240 landscape display for a compact product/transport header, a
friendly face and allowlisted activity, three aligned CPU/RAM/GPU cards with
rounded whole percentages, actual received-sample trends and utilization bars,
then truthful measured battery voltage and last dashboard update age. Unknown
readings remain `--`; do not invent battery percentage, elapsed session time,
CPU temperature or connection detection. Age describes received data, not
connectivity. Keep all display strings bounded and exclude private content.

Keep rendering local, bounded and incremental; retain a restrained blink only
when appropriate, and suppress it in Quiet mode. No head commands during screen
verification. No additional application or firmware dependencies, flashing,
calibration, reset or persistent device-file writes.

Create previews by executing the actual firmware renderer with LCD fakes and
synthetic readings. Verify layout isolation, unavailable values, bounded history,
update-age semantics, redraw behavior and all protocol/motion regressions.
Stage Release under artifacts, deploy through normal Quit with backups/hashes,
then load the new companion into RAM and verify the physical USB session.
