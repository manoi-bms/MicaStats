# MicaPad todo productivity recommendations

Research date: 2026-10-06. These are proposed follow-ups, not implemented features. Prioritize improvements that keep tasks in their existing notes and require little extra input. The ordering below is a design recommendation inferred from official product guidance.

1. **A task overview with source navigation.** Collect tasks into Open, Today, Upcoming and Completed views. Show the note title and jump directly to the original checkbox. Microsoft To Do's [My Day and suggestions](https://support.microsoft.com/en-US/ToDo/my-day-and-suggestions) demonstrates a daily focus list without abandoning the underlying task lists. MicaPad's overview should be a derived view; editing remains available in the source note, and opening the overview should never move or duplicate tasks.
2. **Optional due dates and reminders, separate from tracking times.** Start and Finish record actual activity and can now be explicitly corrected. A due date answers a different question: when must this be done? Things distinguishes a planned start from a deadline in its [When and deadlines guidance](https://culturedcode.com/things/support/articles/2803579/); Microsoft To Do offers [due dates and reminders](https://support.microsoft.com/en-US/ToDo/add-due-dates-and-reminders-in-microsoft-to-do). Keep those fields separate and reminders opt-in. Show overdue state in words as well as color.
3. **Quick capture and keyboard task actions.** Add a shortcut to capture a task into a chosen note and a small searchable task action menu. Reuse explicit actions such as Complete, Edit dates, Add to Today and Set due date. Things documents [Quick Entry](https://culturedcode.com/things/support/articles/2803584/?platform=ipad), and Todoist provides [keyboard shortcuts](https://www.todoist.com/help/todoist/features/use-keyboard-shortcuts-in-todoist-Wyovn2). Start with explicit commands and existing date validation rather than an ambiguous natural-language date parser.
4. **Bulk changes with Undo.** Select several tasks in the overview to complete, reopen or postpone them. Show how many tasks will change and make the operation one Undo step. Todoist documents [managing multiple tasks](https://www.todoist.com/help/articles/add-or-manage-multiple-tasks-in-todoist-PcPoskdUp). Keep task identities stable and preserve the source notes and completion history.
5. **Recurring tasks with individual completion history.** Offer fixed-calendar repeats and repeats measured from completion as distinct choices. Things describes these two models in its [repeating tasks guidance](https://culturedcode.com/things/support/articles/3743733/). Each occurrence should have its own identity and tracking dates; completing an occurrence should retain its history while creating the next pending occurrence.

Reliability should accompany each step: regression coverage for Undo/Redo, encrypted metadata persistence, duplicate or moved tasks, restart recovery and backup/restore. Preserve atomic saves and make failed or pending saves visible. A future encrypted task change history could distinguish automatic timestamps from explicit corrections. These reliability proposals are MicaPad design recommendations, not claims made by the referenced products.

Suggested order: overview and source navigation, separate due dates/reminders, quick capture, bulk Undo, then recurrence. Tags and saved filters can follow once real task volume justifies additional organization.
