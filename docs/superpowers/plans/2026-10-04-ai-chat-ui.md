# AI chat UI: richer answers, a resizable pane, activity — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AI answers in Ask MicaStats and in MicaPad show tables, code blocks with Copy, and Mermaid diagrams drawn on this PC; the models are told so; MicaPad's side pane is resizable; and both places say what the assistant is doing and how long it took.

**Architecture:** The pure parser `ChatMarkdown` learns tables and whether a code fence is closed. `ChatDocument` turns those into WPF blocks, taking a `ChatRender` with what it needs from outside (clipboard, diagram pictures, theme). A small adapter, `ChatDiagrams`, gets pictures from MicaPad's existing `IDiagramRenderer` (a hidden, network-blocked browser page) and tells its caller to draw again when one arrives. The AI pane, the Ask window and the splitter are view changes over existing state objects (`AiSession`, `AskTurnView`).

**Tech Stack:** C# / .NET 8 / WPF, ModernWpf, AvalonEdit (MicaPad's editor), WebView2 through the existing `DiagramPage`, xUnit 2.9.2.

**Spec:** `docs/superpowers/specs/2026-10-04-ai-chat-ui-design.md` (binding). The MicaPad AI specs still bind the AI pane and the note tools: `docs/superpowers/specs/2026-10-03-micapad-ai-writing-and-answers-design.md` and `docs/superpowers/specs/2026-10-04-micapad-ai-note-tools-and-diagrams-design.md`.

## Global Constraints

- **Nothing is fetched.** Drawing an answer makes no network request. An image (`![alt](address)`) stays text. No HTML is interpreted. A diagram is drawn only by the local page behind `IDiagramRenderer`, with `KrokiServer: null`, and only for the fence word `mermaid`.
- **Links.** The existing rules do not change. `ChatDocument.RemoveLinks` must leave no `Hyperlink` anywhere in a document, table cells included. MicaPad's answers always go through it; an Ask MicaStats answer does once the conversation read notes.
- **Consent.** Do not move, remove or reorder any `AiIsOff()` check in `Pad/MicaPadWindow.Ai.cs` or `Pad/MicaPadWindow.AskNotes.cs`, or the per-surface checks in `Services/Ai/Tools/MicaTools.cs`. No task adds a path to `runner.RunAsync`.
- **What goes into the note does not change.** Replace selection and Insert below put `AiSession.ResultForNote` in the note: the text, never a rendering.
- **Never throws into the UI.** Rendering runs on timer ticks. Everything that draws an answer catches its own failures and falls back (plain text, a code block with a reason).
- **Clipboard.** Every Copy in an answer goes through `ChatClipboard.SetText`. Tests replace it; no test touches the real clipboard.
- **Exact values:** table limits 12 columns and 100 body rows; 8 diagrams per answer; diagram source at most `DiagramBlocks.MaxSourceLength`; pane width default 360, minimum 260, maximum 900, editor minimum 320; redraw intervals unchanged (100 ms).
- **Exact strings:**
  - code header button: "Copy", then "Copied"; tool tip "Copy code"
  - diagram header: "Diagram", toggle "Source", button "Copy" (tool tip "Copy the diagram's source"); menu "Copy image", "Copy source"
  - "Drawing the diagram…"
  - "This diagram could not be drawn: " followed by the renderer's message
  - MicaPad pane: "Waiting for the model…", "Waiting for {model}…", "Writing…", "Finished in {duration}"; toggle "Source" (tool tip "Show the text as it would be inserted")
  - Ask window: "Thinking…" and the eleven tool lines of spec section 4; "Using {name}…"; footer "{HH:mm} · {duration}"; hint "Enter to send · Shift+Enter for a new line · {used} of {limit} today"; jump button tool tip "Jump to the latest"

  - durations: "4 s" (never less than "1 s"), "1 min 5 s"
- **Logging:** a failure is logged by its exception type only. Never answer text, a diagram's source or note text.
- **Tests:**

### Task 1: Tables and closed fences in the parser

**Files:**
- Modify: `Services/Ai/ChatMarkdown.cs`
- Test: `tests/Kil0bitSystemMonitor.Tests/ChatMarkdownTests.cs`

**Interfaces:**
- Consumes: the existing `ChatRun`, `ChatBlock`, `ChatBlockKind`, `FenceTracker`, `MarkdownLineTokenizer`.
- Produces:
  ```csharp
  public enum ChatAlign { Left, Center, Right }
  public sealed record ChatCell(IReadOnlyList<ChatRun> Runs);
  public sealed record ChatTable(IReadOnlyList<ChatAlign> Aligns, IReadOnlyList<ChatCell> Header, IReadOnlyList<IReadOnlyList<ChatCell>> Rows);
  // ChatBlockKind gains: Table
  // ChatBlock gains:
  public ChatTable? Table { get; }   // set only for Kind == Table
  public bool Closed { get; }        // for Code: its closing fence line was seen; true for every other kind
  // ChatMarkdown gains:
  public const int MaxTableColumns = 12;
  public const int MaxTableRows = 100;
  ```

**Rules:**
- A table is a header line holding at least one unescaped pipe, followed directly by a delimiter line: cells of `-` with an optional `:` at either end, at least one `-` each, separated by pipes, outer pipes optional.
- The delimiter's cell count is the column count. A header with another count is not a table.
- `:---` and `---` are Left, `:---:` Center, `---:` Right.
- Body rows follow until a blank line, a line with no pipe that starts another block (heading, fence, list item, quote, rule), or the end. A body row is padded with empty cells or cut to the column count.
- Cells are split on pipes that are not escaped (`\|` gives a pipe in the cell) and not inside a code span. Each cell is trimmed and parsed with the same inline parser as a paragraph, `MaxInlineLength` included.
- Over `MaxTableColumns` or `MaxTableRows`: no table. Every line is parsed as it is today.
- Inside a list item or a quote there are no tables (only at the top level).
- A code block's `Closed` is false only when the text ends inside the fence.
- Nothing else about the parser changes; text is never lost.

  - alignment from the delimiter row;
  - outer pipes optional; a short row padded, a long row cut;
  - `\|` and a pipe inside a code span stay in the cell;
  - bold, code and a link inside a cell are runs;
  - a header line without its delimiter line is a paragraph, and becomes a table once the delimiter is appended (the streaming case);
  - a table ends at a blank line and at a heading;
  - 13 columns, and 101 body rows: no table, and the joined text of all blocks still holds every cell's text;
  - a line of 4,000 pipes parses in bounded time and loses nothing;

  ```csharp
  internal enum ChatDiagramStatus { Off, Drawing, Drawn, Failed }
  internal sealed record ChatDiagramState(ChatDiagramStatus Status, ImageSource? Picture = null, double Width = 0, double Height = 0, string? Error = null);
  internal interface IChatDiagrams
  {
      /// The state of the picture for this Mermaid source in this theme. Starts a draw when none was started.
      /// whenDone is called once, on the UI thread, when a draw this call is waiting for ends.
      ChatDiagramState Get(string source, bool dark, Action? whenDone);
      /// Forgets every picture and every remembered failure.
      void Clear();
  }
  internal sealed class ChatDiagrams : IChatDiagrams
  {
      public const int MaxPerAnswer = 8;
      public ChatDiagrams(Func<IDiagramRenderer?> renderer, Func<bool> enabled);
      /// The app's own, set at startup; null before that and in tests.
      internal static IChatDiagrams? Current { get; set; }
  }
  // ChatRender gains:
  public IChatDiagrams? Diagrams { get; init; }
  public bool Dark { get; init; } = true;
  public Action? Invalidate { get; init; }
  public ISet<string> SourceShown { get; init; }   // sources whose Source toggle is on; owned by the view, so it survives a redraw
  // AskTurnView gains:
  internal IChatDiagrams? Diagrams { get; set; }   // default ChatDiagrams.Current
  internal void ApplyTheme(bool dark);
  // PadAnswerBox gains:
  internal IChatDiagrams? Diagrams { get; set; }   // default ChatDiagrams.Current
  public void Clear();                              // empties the box, its Source set, and calls Diagrams?.Clear()
  ```

**Rules:**
- `ChatDiagrams.Get`:
  - `Off` when `enabled()` is false or `renderer()` is null;
  - `Failed` with `DiagramText.TooLarge` when the source is longer than `DiagramBlocks.MaxSourceLength`;
  - a remembered outcome for this source and theme is returned as it is (`Drawn` or `Failed`): **a failure of any kind is remembered and not retried** until `Clear()`, so a failed draw cannot cause an endless redraw;
  - otherwise `Drawing`: the first call for a key starts `RenderAsync` (kind `mermaid`, `KrokiServer: null`, a slot object of its own); later calls for the same key only add their `whenDone`.
  - When the draw ends, on the UI thread: remember the outcome (a frozen bitmap for a picture), then call each waiting `whenDone` once. A `whenDone` that throws is caught.
  - It keeps at most 32 outcomes, least recently used out.
  - Nothing throws: an exception is logged by type and the outcome is `Failed` with `DiagramText.Failed`.
- `ChatDocument`:
  - a `Code` block with language `mermaid` (any letter case), `Closed`, `render.Diagrams != null`, and fewer than `MaxPerAnswer` diagrams before it in this document, becomes a diagram block; anything else is a code block as in Task 2;
  - `Off`: a code block;
  - `Drawing`: "Drawing the diagram…" (muted) above the source as a code block;
  - `Drawn`: a box with the header ("Diagram", the **Source** toggle, **Copy**) and the picture: `Stretch.Uniform`, `StretchDirection.DownOnly`, its own size as maximum, left-aligned. Right-click: **Copy image** (through a replaceable hook, `ChatClipboard.SetImage`, default the real clipboard with failures logged by type) and **Copy source**;
  - **Source** on: the code in place of the picture; the source's text is added to or taken from `render.SourceShown`, so a redraw keeps the choice;
  - `Failed`: the source as a code block, and under it "This diagram could not be drawn: " + the message (`Ask.Muted`, wrapping).
- `AskTurnView`: builds with `Diagrams`, `Dark`, its own `SourceShown` set, and `Invalidate` = render again if the turn is still shown. `ApplyTheme(dark)` renders again when it has rendered. `AskWindow` gives each new turn its theme and calls `ApplyTheme` on every turn when the theme changes.
- `PadAnswerBox`: the same, with its `_dark`; an invalidate shows `Shown` again when it shows Markdown. `ApplyTheme` renders again. `Clear()` as above.
- `App`: move the creation of the diagram renderer out of `OpenPad` into one method that creates it on first use (`OpenPad` and the chat both call it), and set `ChatDiagrams.Current = new ChatDiagrams(thatMethod, () => config.PadDiagrams)` at startup. **Interfaces:**
- Produces:
  ```csharp
  internal static class PaneWidth
  {
      public const double Default = 360, Min = 260, Max = 900, EditorMin = 320;
      /// The pane's width for a wanted width and the width of the editor area: within Min and Max,
      /// leaving EditorMin for the editor; Min when the area is too narrow for both. NaN or not positive: Default first.
      public static double Fit(double wanted, double areaWidth);
  }
  // AppConfig:
  public double PadPaneWidth { get; set; }   // default 360; a value that is NaN, infinite or outside 260..900 is stored as the nearest limit, NaN as the default
  ```

**Rules:**
- `EditorArea` gets three columns: the editor (`*`), the splitter (`Auto`), the pane (a pixel width). The splitter is a `GridSplitter` 5 wide, `ResizeBehavior="PreviousAndNext"` or equivalent, focusable, with the tool tip, in the `Pad.Border` colour, shown only while a pane is shown.
- With no pane shown, the splitter is collapsed and the pane column takes no room.
- When a pane is shown, when the window is resized, and when the config value changes: the pane column's width is `PaneWidth.Fit(config.PadPaneWidth, EditorArea.ActualWidth)`.

### Task 8: Redraws that keep up (added during the build; runs before Task 7)

Measured after Task 2 (Debug build): one redraw of an answer with a table costs 25 ms at 10 by 4, 106 ms at 30 by 6 and 623 ms at 100 by 12, against a redraw timer of 100 ms. And the Task 2 review found that a click on a button inside a streaming answer can be lost, because every redraw replaces the button.

**Files:**
- Create: `Ai/RedrawPace.cs`
- Modify: `Ai/AskTurnView.cs`, `Pad/AiPane.xaml.cs`, `Pad/SearchPane.xaml.cs` (only its answer's redraw throttle)
- Test: `tests/Kil0bitSystemMonitor.Tests/RedrawPaceTests.cs` (new), `AiAskTurnViewTests.cs`, `AiPaneTests.cs`, `SearchPaneAskTests.cs`

**Interfaces:**
- Produces:
  ```csharp
  internal static class RedrawPace
  {
      public const int Share = 4;                                        // a redraw may take one part in five of the time
      public static readonly TimeSpan Longest = TimeSpan.FromSeconds(2);
      /// The shortest time from one redraw to the next: at least `least`, at least Share times `lastCost`,
      /// at most Longest, and never less than `least`. A negative cost counts as zero.
      public static TimeSpan Next(TimeSpan least, TimeSpan lastCost);
  }
  // Each of the three views gains:
  internal TimeSpan LastRedrawCost { get; set; }    // measured by the view; tests set it
  internal Func<bool> PointerHeld { get; set; }     // default: the left mouse button is down and the pointer is over the answer box
  ```

**Rules:**
- The cost of a redraw is the time from its start until the dispatcher reaches `DispatcherPriority.Loaded` after the document was shown (a callback posted there runs after the layout and render pass). It is stored in `LastRedrawCost`. If the view is gone by then, nothing is stored.
- Where a view today waits `RenderInterval` (or `RedrawInterval`) between two redraws of a streaming answer, it waits `RedrawPace.Next(thatInterval, LastRedrawCost)`.
- When the redraw timer fires while `PointerHeld()` is true, nothing is drawn and the timer is started again for the plain interval.
- A draw that is not a timed redraw of a streaming answer is never delayed: the first text, the end of the answer (`Complete`, a finished view), another request's view, a theme change, a picture that arrived.
- `PointerHeld` must never throw into a tick: a failure counts as not held.
- Nothing else about what is drawn changes.
- One line in the parser, from the re-review of Task 1: `ChatMarkdown`'s delimiter check returns at once for a line that holds no pipe at all (`IndexOf('|') < 0`), before it splits the line. Today every paragraph line's next line is split, with its copies, for answers that hold no table. No behaviour changes; the existing tests are the proof. Add `Services/Ai/ChatMarkdown.cs` to this task's files for that line only.

  - each view: after a redraw with `LastRedrawCost` set to 300 ms, the next streamed text does not draw at once and the timer waits 1.2 s (read the timer's interval through an internal property; do not sleep);
